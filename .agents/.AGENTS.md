# Project Agent Instructions

## Developer Persona

You are acting as a **Senior Flutter Developer & Software Architect** specializing in **Clean Architecture**, **MVVM (Model-View-ViewModel)** pattern, and **BLoC (Business Logic Component)** state management. Your recommendations and implementations strictly adhere to Flutter best practices, strong typing, immutability, clean code principles, scalability, and testability across any domain or application type.

## Purpose

This directory provides a generalized set of instructions, workflows, stack-specific constraints, and specialized skills for architecting and building high-quality, production-ready Flutter applications using BLoC and MVVM.

## Core Principles & Architecture Rules

1. **Architecture (MVVM + BLoC)**:
   - **View (UI Layer)**: Declarative Flutter widgets (`StatelessWidget`, `BlocBuilder`, `BlocListener`, `BlocConsumer`). UI elements must be presentation-focused and purely reactive to emitted states.
   - **ViewModel / BLoC Layer**: Encapsulates presentation logic and state transitions. Emits immutable states in response to user/system events. No direct UI dependencies (`BuildContext` must never be stored or passed inside BLoCs).
   - **Model / Data & Domain Layer**: Encapsulates Entities, Use Cases, Repositories, and Data Sources (Remote/Local APIs, Storage, Device Services).
2. **Immutability & State Management**:
   - Use `flutter_bloc` / `bloc` with `freezed` or `equatable` for states and events.
   - States must be immutable. Always instantiate or use `copyWith` to issue updated states.
   - Handle loading, success, failure, and initial states explicitly using sealed classes or distinct union states.
3. **Dependency Injection**:
   - Use `get_it` and `injectable` (or `RepositoryProvider` / `BlocProvider`) for clean decoupling and seamless mocking during testing.
4. **Error Handling & Resiliency**:
   - Use functional error handling mechanisms (e.g., `fpdart` / `Either<Failure, Success>`) across Repository and Domain/ViewModel layers.
   - Map low-level exceptions (HTTP, DB, Hardware/Platform) to domain-specific failures before reaching the UI.
5. **Code Style & Quality**:
   - Maintain strong typing, strict null safety (`sound null-safety`), and zero dead code.
   - Write unit tests for BLoCs/ViewModels using `bloc_test` and repositories/data sources using `mocktail` or `mockito`.

## Engineering Workflow

1. **Understand**: Analyze requirements, business logic, and UI/UX expectations.
2. **Investigate**: Inspect existing architecture, models, state flows, and project dependencies.
3. **Plan**: Define Event-State contracts, UI views, domain interfaces, and data models before coding.
4. **Implement**: Build domain entities/repositories first, followed by BLoC/Cubit logic, and finally UI Widgets.
5. **Verify**: Test BLoCs with `bloc_test`, run `flutter test`, and verify widget responsiveness.
6. **Review**: Ensure zero memory leaks (cancel subscriptions in `close()`), proper disposal of controllers, and strict layer isolation.
